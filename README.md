# discord-in-office

디스코드를 **투박한 Excel 화면으로 위장**해 주는 Electron 래퍼.
도서관·사무실처럼 화면이 노출되는 공간에서 디스코드를 쓸 때 눈치를 덜 보게 해 준다.

## 동작 방식

- 디스코드 웹(`discord.com/app`)을 Electron 창에 띄우고 CSS/JS를 주입한다.
- 주입 요소:
  - 상단 초록 **리본 바**(파일·홈·삽입… 탭) + **수식 막대** (`=SUMIF(C:C,"회의",H:H)`)
  - 하단 **시트 탭** (Sheet1 · 채팅로그 · Sheet3) + 상태 표시줄(시계)
  - 메시지 목록 왼쪽에 **행번호 세로줄**, 메시지마다 격자선
  - 서버 아이콘은 회색조로 눈에 덜 띄게 처리
  - 메시지를 클릭하면 수식 막대가 `="메시지 내용"` 처럼 반응 (셀 클릭 흉내)
  - 창 제목은 항상 `재고관리_2026.xlsx - Excel` 로 고정
  - 디스코드 다크 테마를 **강제로 라이트로 스왑** (`theme-dark` → `theme-light`).
    UI 리프레시로 변수 오버라이드가 무시돼도 테마 클래스 스왑은 항상 통한다.
- 이모지 가시/비가시 옵션:
  - **보기 → 이모지 숨기기 (⌘E)** 로 토글. 설정은 재시작 후에도 유지.
  - 비가시 모드에서는 이모지 이미지 대신 노란 셀 노트 스타일의 `[눈물웃음]`,
    `[엄지업]` 텍스트가 나온다. 커스텀 이모지는 `[:이모지이름:]`.
  - **스티커**는 디스코드가 내장 렌더하는 이름을 그대로 `[스티커:시오짱]`으로 표기.
    스티커 자리는 한 줄로 접혀 공간을 차지하지 않고, **라벨을 누르면 원본이
    펼쳐지고** 다시 누르면 접힌다.
  - **사진**(첨부·임베드 이미지)은 한 줄 높이로 접혀 `눌러서 사진보기` 버튼만 남는다.
    **버튼을 누르면 자리에서 펼쳐지고**, 그 자리에 남는 `사진 접기` 버튼(또는 사진
    자체를 다시 누르면)으로 접는다. 버튼을 남기는 건 사진을 눌러도 접힌다는 걸
    알 방법이 없기 때문이다.
    캐러셀(1/4)은 묶음 단위로 함께 펼쳐진다.
  - **링크 임베드**(유튜브 등)는 컨테이너째 접혀 `[임베드:youtube.com]` 라벨만 남는다.
    안의 iframe 플레이어도 함께 숨는다. 라벨을 누르면 플레이어까지 펼쳐지고,
    그 자리에 남는 `[임베드 접기]`를 누르면 다시 접힌다.
    스티커·사진과 달리 **원본을 눌러서는 접히지 않는다** — 임베드 안에는 제목
    링크가 있어서, 원본 클릭을 가로채면 링크를 못 누르게 되기 때문이다.
  - **프로필 사진**은 이니셜 회색 셀로 마스크, 아바타 장식·역할 아이콘·클랜 배지는 숨김.
    단 **채팅 목록에서는 이니셜 박스도 함께 없앤다** — 결국 자리를 차지하므로
    닉네임만 남기는 편이 낫다. 멤버·친구 목록에서는 누구인지 구분해야 하니 그대로 둔다.
    메시지 목록뿐 아니라 음성 채널 멤버·유저 패널·답장 아바타까지 포함하며,
    `<img>`가 아니라 인라인 `background-image`로 그려지는 자리도 함께 지운다.
  - **길드 아이콘·길드 배너**도 숨김 모드에서 함께 제거.
  - **텍스트 이모지**(상태 메시지·채널명 등 유니코드 문자)도 같은 방식으로 설명 표기.
- 서버·채널 이름은 **모드와 무관하게 항상 감춘다**:
  - 상단 바(서버 이름 + 받은편지함·도움말 아이콘)를 통째로 없앤다.
  - 채널 헤더의 채널 이름을 감춘다.
  - 검색창 안내문 `히키특수학교 검색` → `검색` (서버 이름만 제거).
  - 채널 헤더의 **설명(주제)** 도 함께 감춘다.
  - 입력창 안내문 `#채널명에 메시지 보내기` → `값을 입력하십시오`.
  - 이름은 "이건 엑셀이 아니다"를 가장 크게 알리는 요소라 토글에 걸지 않았다.
    지금 어느 채널인지는 좌측 패널을 펴면(⌘⇧B) 확인할 수 있다.
  - 감추기는 CSS 가, 문구 치환은 `scanChromeText()` 가 맡는다 — CSS 로는
    텍스트를 갈아끼울 수 없기 때문이다. 문구 치환은 안내문 형태일 때만
    동작하도록 정규식으로 한 번 더 거른다(검색 결과를 덮어쓰지 않도록).
- 좌측 패널 접기 옵션:
  - **보기 → 서버·채널 목록 숨기기 (⌘⇧B)** 또는 리본의 **탐색 창** 버튼으로 토글.
  - 이 상태는 **저장하지 않는다.** 접어둔 채로 껐다가 켜면 지금 어느 채널인지
    알 수 없는 화면으로 시작해서, 눌린 줄도 모르고 헤매게 된다. 늘 펴진 채로
    시작하고, 접는 건 그 세션 동안만 유지한다.
  - 서버 목록과 채널 목록을 통째로 없애 워크시트 영역만 남긴다. 채널을 옮길 때만
    잠깐 펴면 된다. `Ctrl+B`는 디스코드 입력창의 굵게 서식이라 피했다.

## 강제 라이트 테마의 원리

2025년 UI 리프레시 이후 디스코드는 테마 토큰을 CSS 파일에 직접 정의하고
선언 순서 때문에 `theme-darker`(Onyx)가 이긴다. 클래스 스왑만으로는 못 이기므로,
페이지 안에서 같은 오리진의 CSS 원문을 fetch해 `theme-light` 블록의 토큰
(약 600개)을 전수 추출한 뒤 `!important`로 재정의한다. 다크 클래스가 살아
있어도 값 자체가 라이트로 고정된다.

## 실행

```bash
npm install
```

| 명령 | 시작 상태 |
| --- | --- |
| `npm start` | **가린 상태**(이모지·사진·임베드·프로필) — 기본값 |
| `npm run start:visible` | 아무것도 가리지 않은 상태로 시작 |
| `npm run start:stealth` | 가린 상태 + **서버·채널 목록까지 접고** 시작 |

가리는 것이 기본이다. 위장이 목적인 도구가 안 가려진 채로 뜨면 앞뒤가 맞지 않는다.
잠깐 원본을 보려면 `Ctrl+E` 로 토글하면 된다.

CLI 플래그(`--dio-visible`, `--dio-hidden`, `--dio-nopanel`)는 **그 실행에만** 적용되고 저장되지 않는다.
`start:visible`을 한 번 썼다고 이후 `npm start`가 그 상태로 남지 않는다.
메뉴나 단축키로 토글한 것은 평소대로 저장된다.

첫 실행 시 디스코드 로그인(비밀번호 또는 QR)을 하면 된다.

Windows에서도 동일하게 동작한다. 숨김 토글 단축키만 `Ctrl+E`가 된다.
`DIO_DEBUG=1 npm start`로 실행하면 화면 캡처(`%TEMP%\dio-shots`)와
원격 스크립트 실행(`%TEMP%\dio-exec.js`) 디버그 루프가 켜진다.

## 테스트

```bash
npm test
```

픽스처만 쓰는 오프라인 스위트다(가림 · 펼치기 · 성능 · 리본 · 번들 구조, 81개 검사).
네트워크를 타지 않으므로 빠르고 결과가 흔들리지 않는다.

```bash
npm run test:launch
```

실제 앱을 띄워 **실행 플래그 · 단축키 · 설정 저장**을 확인한다(10개 검사).
`main.js` 는 Electron 메인 프로세스에서만 도는 코드라 픽스처로는 닿지 않는다.
특히 *일회성 CLI 플래그가 저장 설정을 오염시키지 않는가* 를 본다 — 실제로
`--dio-visible` 로 띄운 뒤 패널만 토글하면 `emojiVisible: true` 가 저장돼서
다음 `npm start` 가 가려지지 않은 채 뜨는 버그가 있었다.
`userData` 는 임시 폴더로 격리하므로 실제 설정을 건드리지 않는다.
창을 실제로 띄우므로(숨긴 창은 rAF 가 멈춰 결과가 왜곡된다) **도는 동안 창을
닫지 말 것** — 닫으면 그 사실을 알리고 실패로 잡는다.

```bash
npm run test:live
```

실제 `discord.com` 에 주입해서 부팅과 라이트 테마 강제를 확인한다.
라이트 토큰 추출은 디스코드 CSS 원문을 실제로 받아와야 성립하므로 픽스처로는
절대 확인할 수 없다 — 그래서 이 테스트가 따로 있다. 네트워크가 필요하다.

### 왜 필요한가

이 코드는 디스코드가 클래스 이름을 바꾸면 **조용히 깨진다.** 실제로
`[class*="avatar"]` 가 대소문자 탓에 `voiceUserAvatar__해시` 를 놓치던 버그와,
"눌러서 사진보기" 버튼이 `display:none` 으로 남아 눌리지 않던 버그가 화면을 눈으로
보기 전까지 드러나지 않았다. `test/fixtures/` 는 그 형태들을 그대로 재현해 둔 것이다.

- `masking.html` — 캐멀케이스 아바타, 배경이미지 아바타, 중첩 임베드, 스티커,
  단일 사진, 캐러셀 묶음, 그리고 서버·채널 이름이 실제로 들어 있던 크롬 4종
  (상단 바 · 채널 헤더 · 검색창 · 입력창). 클래스와 중첩은 실제 디스코드 DOM 을
  콘솔로 떠서 그대로 옮겼다 — 눈대중으로 선택자를 짜다 두 번 당했기 때문이다.
- `chat.html` — 약 4,500 노드에 60ms마다 4행이 교체되는 부하. 스캔 누적 시간과
  메인스레드 블로킹에 상한을 걸어 두어, 예전의 "모든 변이마다 전체 문서 재스캔"
  구조로 되돌아가면 반드시 실패한다.

로그인된 상태의 UI 는 자동 검증하지 못한다. 그 부분은 직접 확인해야 한다.

## 조작

| 단축키 | 동작 |
| --- | --- |
| ⌘E | 이모지 가시/비가시 토글 |
| ⌘⇧B | 서버·채널 목록 접기/펴기 |
| ⌘R | 새로고침 |

앞의 둘은 리본에도 버튼으로 있다(**내용 가리기** · **탐색 창**). 단축키만 두면
모르는 사람은 쓸 수 없고, 지금 눌려 있는지도 알 수 없다. 버튼은 켜져 있을 때
눌린 표시가 난다.

버튼 클릭은 `preload.js` 의 통로로 메인 프로세스에 전달된다. 단축키·메뉴와 같은
곳으로 모아야 설정 저장과 메뉴 라벨 갱신이 어긋나지 않는다.

단축키는 메뉴 액셀러레이터가 아니라 메인 프로세스의 `before-input-event`에서
가로챈다. 디스코드 웹이 `Ctrl+E`(이모지 피커) 같은 키를 자체 처리해 버리기
때문에, 렌더러보다 먼저 도는 곳에서 잡아야 실제로 먹는다. 메뉴에 표시되는
액셀러레이터는 `registerAccelerator: false`로 표시 전용이다(이중 발동 방지).

## 구조

```
main.js              Electron 메인 — 창 · 설정 · 메뉴 · 단축키 · 주입
preload.js           리본 버튼 → 메인 프로세스 통로 (contextBridge)
bundle.js            src/*.js 를 순서대로 이어붙여 주입용 소스로 만든다
excel.css            엑셀 위장 스타일 (주입용)
src/
  01-core.js         IIFE 시작, DIO 전역, 스캔 스코프/캐시, 선택자(SEL)
  02-chrome.js       리본 · 수식 막대 · 시트 탭 · 상태 표시줄
  03-emoji-dict.js   이모지 → 한글 설명 사전
  04-theme.js        강제 라이트 테마
  05-collapse.js     접기/펼치기 공통 골격, 펼침 상태 저장소
  06-scan.js         스캔 패스 (이모지 · 스티커 · 임베드 · 사진 · 프로필 · 텍스트)
  07-boot.js         스캔 스케줄러와 진입점, IIFE 닫기
test/                픽스처 기반 테스트 (아래 참고)
```

`src/*.js` 는 **하나의 IIFE 를 나눠 가진 조각들**이다. 파일명 앞 번호 순서로
이어붙여야 문법이 성립하므로, 조각 하나만 놓고 `node --check` 를 돌릴 수 없다.
대신 `npm test` 가 이어붙인 번들 전체를 파싱하고, IIFE 를 닫은 뒤에 코드가
남지 않았는지(= 순서가 어긋나지 않았는지)까지 확인한다.

## 커스터마이징

- 파일명·수식 문구: `src/01-core.js` 의 `FILE_NAME`, `src/02-chrome.js` 의 `buildChrome()`
- 리본 색: `excel.css`의 `#217346`(엑셀 그린)
- 이모지 설명 사전: `src/03-emoji-dict.js` 의 `EMO` 객체 (없는 이모지는 `[원문]`으로 표기)
- 디스코드 선택자: `src/01-core.js` 의 `SEL` — UI 개편으로 클래스명이 바뀌면 여기만 고치면 된다

## 주의

### 위장이 통하는 범위

이 도구는 **사람 눈**을 대상으로 한다. 옆자리에서 흘끗 보는 시선까지가 유효 범위고,
기계가 남기는 흔적은 하나도 가려주지 않는다.

- 작업 관리자에 뜨는 프로세스는 `electron.exe`다. Excel이 아니다.
- `discord.com` · `gateway.discord.gg` · `cdn.discordapp.com` 트래픽은 프록시·DNS 로그에
  그대로 남는다. 게이트웨이 WebSocket을 상시 물고 있어 접속 체류시간이 길게 잡힌다.
- 작업표시줄 아이콘, Alt+Tab 미리보기, 화면 공유에는 위장이 적용되지 않는다.
- **OS 알림 권한은 기본으로 거부한다.** 알림 팝업에 보낸 사람과 메시지 내용이
  그대로 떠서 위장이 통째로 무의미해지기 때문이다. 알림을 받고 싶으면
  `main.js` 의 `ALLOWED_PERMS` 배열에 `'notifications'` 를 넣으면 된다.
- **링크는 앱 안에서 열지 않고 기본 브라우저로 넘긴다.** 엑셀이 아닌 창이
  앱 안에서 뜨는 것보다 낫고, 임의 웹 콘텐츠를 Electron 창에서 돌리지 않는 편이
  보안상으로도 맞다.

### 디스코드 약관

공식 클라이언트를 수정하지 않는다. `discord.com/app`(웹 클라이언트)을 Electron 창에 띄우고
렌더된 페이지에 CSS·DOM을 얹을 뿐이라, 층위로는 BetterDiscord보다 유저스크립트에 가깝다.
토큰 접근·API 직접 호출·메시지 자동 전송·게이트웨이 조작은 **전부 없다.**

Discord ToS 9조("copy, modify, create derivative works based upon")에 형식상 걸릴 소지는
있으나, 실제 제재가 나가는 행위(자동화·셀프봇·API 남용)는 여기에 해당하지 않는다.
DOM을 어떻게 그렸는지는 서버로 전송되지 않으므로 탐지 경로도 사실상 없다.
제재 위험은 낮지만 0은 아니니, 신경 쓰이면 부계정을 쓰면 된다.

### `DIO_DEBUG=1`은 개발 전용

실사용 환경에서 켜지 말 것. 켜면 두 가지가 동작한다.

- 5초마다 **화면 전체를 캡처**해 `%TEMP%\dio-shots`에 PNG로 계속 쌓는다.
  로그인된 대화 내용이 평문 이미지로 디스크에 남는다.
- `%TEMP%\dio-exec.js`에 놓인 **임의의 JS를 디스코드 세션 컨텍스트에서 실행**한다.
  temp에 파일을 쓸 수 있는 아무 프로세스나 당신 계정으로 코드를 돌릴 수 있다는 뜻이다.

### 기타

디스코드 UI 구조가 바뀌면 일부 스타일이 깨질 수 있다
(선택자는 `[class^=...]` 와일드카드 기반이라 어느 정도 버틴다).

클래스 부분일치 선택자에는 **`i` 플래그가 필수**다. CSS 속성 선택자는 값의
대소문자를 구분하므로 `[class*="avatar"]`는 `avatar__해시`만 잡고
`voiceUserAvatar__해시` 같은 캐멀케이스는 놓친다. 새 선택자를 추가할 때
`[class*="..." i]` 형태를 유지할 것.
